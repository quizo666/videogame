# PixelForge Studio — подготовка спрайтов и монтаж катсцен

Запуск: дважды нажмите **PixelForge.exe**. Установка, Python, подписка и интернет для работы не нужны. Приложение использует встроенный .NET Framework 4.8 и видеодекодеры Windows. Исходные файлы никуда не отправляются.

## Быстрая проверка

Нажмите **Демо**: появится анимация из восьми кадров. Выберите кадр внизу. Прокрутите левую панель вниз до раздела правки. Попробуйте карандаш, ластик, пипетку и экспорт.

## Подготовка видеогенерации

- Неподвижная камера, без зума и смены ракурса.
- Чистый однотонный фон без теней, градиента и текстуры. Например, ярко-зелёный #00FF00, если зелёного нет на персонаже.
- Персонаж целиком в кадре, стопы и голова не обрезаны. Для цикла ходьбы удобна ходьба на месте.
- Постоянные масштаб и положение персонажа; одинаковые освещение и дизайн во всех кадрах.
- Для начала достаточно короткого ролика на 1–3 секунды.

Пример запроса генератору: «Один персонаж, вид сбоку, полный рост, цикл ходьбы на месте, неподвижная камера, постоянный размер и дизайн персонажа, ровный ярко-зелёный фон #00FF00 без теней, без движения камеры, без motion blur, pixel art».

## Рабочий процесс

1. **Открыть видео**, задать FPS и лимит кадров, затем **Извлечь из видео**. Также можно импортировать последовательность PNG с одинаковым размером холста. PNG сортируются по имени: используйте имена `frame_0001.png`, `frame_0002.png` и т. д.
2. Задать размер ячейки в пикселях исходного изображения. Например, исходник 288 × 288 при ячейке 6 даёт спрайт 48 × 48. Кнопка подбора предлагает размер по повторяемости границ в первом кадре; это приблизительная оценка. Для неровно сгенерированного pixel art часто нужен ручной подбор.
3. Автоцвет по краям включён по умолчанию: при импорте фон определяется отдельно для каждого кадра. Кнопка «Удалить фон» обрабатывает всю анимацию с текущими настройками. Для ручного выбора нажмите «Выбрать фон кликом», кликните по фону исходного кадра и нажмите «Удалить фон». Esc отменяет выбор. Также можно указать цвет фона в HEX и допуск. Допуск — максимальное различие по каждому RGB-каналу. Чем он выше, тем больше похожих цветов исчезнет. Нажать **Применить ко всем кадрам**.
4. При необходимости изменить сдвиг X/Y от 0 до размера ячейки минус 1, чтобы сетка лучше совпала с деталями. Сдвиг обрезает соответствующую полосу слева/сверху и оставляет прозрачные ячейки справа/снизу. Размер общего холста остаётся постоянным.
5. Уровни на канал задают общее округление цветов. 8 уровней — до 512 возможных RGB-цветов, а не палитра из 8 цветов. Меньшее значение сильнее упрощает оттенки.
6. Выбрать кадр и исправить его. ЛКМ рисует, ПКМ стирает; инструмент «Пипетка» берёт цвет, Ctrl+Z отменяет штрих. Рисование работает на обработанном кадре. Отключите «Показать исходник», если включали сравнение.
7. **Экспорт кадра** сохраняет выбранный PNG в исходном разрешении спрайта, с прозрачностью. **Все PNG + sheet** создаёт новую папку с отдельными кадрами, `spritesheet.png` и `animation.json` (размеры, число кадров, столбцы, FPS). Укажите имя новой папки в диалоге; расширение `.folder` служит только для выбора имени.
8. **Сохранить проект** сохраняет файл `.pxf` с исходными кадрами, параметрами и ручными правками. Его можно открыть позже без исходного видео. Экспорт PNG не заменяет сохранение проекта.

## Что делает алгоритм

Все кадры обрабатываются на одной сетке с одним размером ячейки и сдвигом. Каждая ячейка становится одним пикселем. Цвет выбирается по наиболее частому округлённому цвету внутри ячейки; если менее половины её площади занимает непрозрачное содержимое, ячейка становится прозрачной. Экспорт имеет бинарную альфу (0 или 255), без сглаживания и полупрозрачных краёв.

## Ограничения этой версии

- Это прототип приведения к сетке, а не нейросеть восстановления рисунка. Он не исправляет анатомию, меняющийся силуэт, пропавшие детали или перемещение персонажа. Общая сетка сама по себе не устраняет всё мерцание анимации.
- Выделение персонажа основано на цвете фона. Сложный фон, тени и совпадение цвета одежды с фоном требуют ручной правки. Нейросетевой сегментации пока нет. Опция «Только фон, связанный с краем» защищает замкнутые детали похожего цвета внутри персонажа; она выключена по умолчанию, чтобы удалялся и фон между руками/ногами. Автоцвет использует наиболее частую группу цветов на краях кадра, поэтому персонаж не должен занимать большую часть границ. Старые проекты .pxf открываются; новые сохраняются с настройками удаления фона.
- Повторное применение обработки заменяет ручные правки; приложение запрашивает подтверждение. Сначала сохраняйте проект.
- Видео длиннее установленного лимита обрабатывается только с начала. Выбора временного участка пока нет.
- Для памяти видео уменьшается до 768 px по длинной стороне; PNG не уменьшаются. До 240 кадров и 32 млн исходных пикселей на последовательность.
- Видео извлекается через Windows MediaPlayer с ожиданием после перемотки. Это приблизительное извлечение с заданным FPS, без гарантии точного соответствия каждому исходному кадру и без чтения исходных временных меток. На тяжёлых роликах возможны пропуски/повторы. Для точной последовательности используйте импорт заранее извлечённых PNG. Проверен синтетический AVI; MP4 конкретного генератора ещё нужно проверить. Если кодек не поддерживается Windows, используйте другой формат или PNG.
- Стабилизация цветов и удержание неподвижных деталей доступны в подготовке кадров и монтаже; экспорт GIF — в монтаже и генераторе фонов. Автоматической обрезки по персонажу и удаления дублирующихся кадров пока нет.

## Исходный код и сборка

Код: `src/PixelForge.cs`. Сборка: `powershell -ExecutionPolicy Bypass -File .\build.ps1`. Используется системный C#-компилятор .NET Framework; SDK и NuGet не требуются.

Автопроверка: `PixelForge.exe --self-test <абсолютная_папка>`. Она создаёт демо, проверяет прозрачность, PNG, размещение спрайтов и двоичное хранение кадров проекта, сохраняет отчёт `checks.txt` и снимок отрисованного окна `preview.png`. Для проверки видео положите синтетический AVI 96 × 96 с разными кадрами в эту папку под именем `test.avi`.

Приложение теперь состоит из четырёх вкладок. «Подготовка спрайтов» содержит весь прежний редактор. «Монтаж катсцен» — сборка многослойных сцен с анимацией и экспортом MP4/GIF. Третья вкладка «Фон из фото» создаёт спокойную периодическую анимацию по маскам. Инструкция по фонам: BACKGROUNDS.md. Инструкция по монтажу: CUTSCENES.md. Готовая демонстрация и её экспорты: examples/cutscene-demo.cutscene, examples/cutscene-demo.mp4, examples/cutscene-demo.gif.


## Очистка цветной каймы (версия 3)

Кнопка **«Очистить кайму»** пересчитывает всю последовательность из исходных кадров. Для существующего проекта сначала сохраните ручные правки в отдельный .pxf: повторная обработка заменяет их, приложение запрашивает подтверждение.

Поле **«Очистка каймы, 0–3»**:
- 0 — выключено;
- 1 — мягкая обработка одного пикселя по краю;
- 2 — стандартная обработка (по умолчанию для новых импортов), полоса до двух пикселей;
- 3 — более сильная очистка, полоса до трёх пикселей.

Алгоритм работает до окончательного округления палитры. Для граничного пикселя он ищет в окрестности до четырёх пикселей подходящий цвет объекта и проверяет модель смешения этого цвета с фоном. Пиксель с преимущественно фоновым содержимым удаляется; при достаточной доле объекта ему присваивается подходящий соседний цвет. Анализ использует неизменённый снимок кадра, чтобы исправленные пиксели не порождали цепочку новых исправлений. Небольшие отдельные компоненты удаляются только при совпадении оттенка с цветом фона; яркие искры другого цвета сохраняются.

Это локальная эвристика, а не распознавание персонажа: синий элемент рисунка, совпадающий с синим фоном, может быть неоднозначен. При потере деталей уменьшите силу очистки до 1 или отключите её (0). Для хорошего результата правильно задайте цвет фона; автоцвет по краям подходит только если фон занимает большую часть границ. Изображения с полностью прозрачной границей в автоматическом режиме сохраняют существующую прозрачность без удаления тёмных цветов.

Новые проекты сохраняются в формате PXF3 вместе с силой очистки. PXF1/PXF2 продолжают открываться, сохранённые кадры не пересчитываются; для них очистка сначала выключена, кнопка «Очистить кайму» включает стандартную силу 2.

Приложение собирается в этой папке командой `powershell -ExecutionPolicy Bypass -File .\build.ps1`. Предыдущий EXE перемещается в `backups`, новый остаётся под именем `PixelForge.exe`. Уже открытое окно продолжает работать со старой версией; перезапустите его, чтобы использовать обновление.

## Интерфейс и ластик для последовательности (версия 4)

Панель настроек подстраивается под доступную ширину; текст переносится с учётом полосы прокрутки. В узком окне настройки размещаются над холстом. Нижние кнопки переносятся без фиксированной высоты панели.

В разделе «Правка кадра» есть список «Ластик применяется к». Выберите «Этому и всем последующим», затем стирайте ластиком или правой кнопкой мыши. Стирание применяется к текущему кадру и всем кадрам после него. Кадры до текущего не меняются. Карандаш всегда рисует только на текущем кадре.

Обрабатываются одинаковые координаты на общем холсте: это маска стирания, а не отслеживание движущейся детали персонажа. Маска распространяется во время новых штрихов после выбора режима; ранее сделанные штрихи автоматически не переносятся. Если на текущем кадре пиксель уже прозрачный, стирание всё равно очищает это место на следующих кадрах. Миниатюры обновляются после завершения штриха.

Ctrl+Z отменяет один целый штрих на всех затронутых им кадрах. Повторное проведение по одному пикселю в рамках штриха не теряет исходное значение. Отмена хранит только изменённые пиксели, а не полные копии всей анимации. Сохранённые .pxf и PNG содержат все внесённые изменения; история отмены остаётся только до закрытия или повторной обработки проекта. Режим ластика при запуске — «Только этому кадру».

## Пиксельная сетка: обработка и линии поверх изображения

«Ячейка в исходнике» определяет блок, который станет одним пикселем результата. Например, исходник 768 × 432 при ячейке 4 превращается в спрайт 192 × 108. Увеличение ячейки уменьшает разрешение и делает детали крупнее; уменьшение ячейки сохраняет больше деталей и исходных неровностей. Размеры округляются вверх, если не делятся на размер ячейки.

В каждой ячейке программа отбрасывает фон и прозрачные пиксели. Если непрозрачного содержимого меньше половины ячейки, она становится прозрачной. Иначе выбирается наиболее частая цветовая группа, а её исходные цвета усредняются. Затем при включённой очистке исправляется кайма и округляется палитра. Все кадры используют одинаковые размер ячейки и сдвиги.

Сдвиг X/Y изменяет начало блоков относительно исходника. «Подобрать размер сетки» предлагает приблизительную оценку по границам первого кадра; результат надо проверить. Параметры изменяют изображение после «Применить ко всем кадрам».

Галочка «Показать линии пиксельной сетки» только рисует границы пикселей поверх предпросмотра при достаточном увеличении. Она не включает и не выключает обработку, не меняет экспорт и не превращает прозрачный шахматный фон в часть изображения. Само выравнивание по сетке не исправляет изменение позы, формы и смещение персонажа между кадрами.




## Единый проект и галерея

Главное меню показывает недавние .pfstudio. Ctrl+S сохраняет все вкладки и используемые ресурсы в один файл, Ctrl+O открывает его. Готовые фоны автоматически попадают в четвёртую вкладку галереи. Подробности и перенос старых файлов: PROJECTS.md.
